# 📘 PROJECT DESCRIPTION

## EduGenie — AI-Powered Study Companion for MCA Students

---

## 1. Introduction

MCA (Master of Computer Applications) students face the challenge of covering a vast technical syllabus within limited time, with most available study material either too lengthy or not aligned with university examination patterns.

EduGenie is a full-stack, AI-powered web application built to address this problem. It generates exam-focused study notes and adaptive quizzes, provides a 24/7 AI tutor, and tracks individual student performance — all structured around the official MCA semester-wise syllabus.

The project is deployed live at: https://edu-genie-ai-assistant.vercel.app

---

## 2. Problem Statement

MCA students commonly face:

- Difficulty understanding complex technical topics (DBMS, OS, CN, Algorithms)
- Lack of exam-oriented, marks-based study material
- No single platform for revision, quizzes, and performance tracking
- Time-consuming preparation across multiple resources
- No visibility into weak areas or progress over time

---

## 3. Proposed Solution

EduGenie provides a centralised, AI-driven academic platform that offers:

- Instant AI-generated study notes per topic
- Adaptive MCQ quizzes with difficulty control and explanations
- A 24/7 conversational AI tutor for academic queries
- Performance analytics with score trends, heatmaps, and weak-area detection
- A structured semester-wise MCA syllabus framework
- Final Year Project (FYP) guidance and an ATS-optimised resume builder

---

## 4. Objectives

1. Develop a full-stack web application for MCA exam preparation
2. Integrate a large language model (LLaMA 3 via Groq API) for content generation
3. Build an adaptive quiz engine with performance tracking
4. Design a relational PostgreSQL database modelling the MCA academic hierarchy
5. Implement secure JWT-based user authentication
6. Deploy the application on cloud infrastructure (Vercel + Render + Neon)

---

## 5. System Architecture

The application follows a three-tier client-server architecture:

```
Browser (React SPA)
        ↓ HTTPS / REST API (Axios + JWT)
Flask Backend (Render — Gunicorn)
        ↓ psycopg2
PostgreSQL Database (Neon — Serverless)
        +
Groq API (LLaMA 3.1 8B) ← called from Flask
```

- Frontend is a Single Page Application (SPA) with client-side routing via React Router
- All API routes are protected using JWT Bearer tokens
- AI content is generated server-side via Groq's inference API — the API key is never exposed to the client
- CORS is configured per-environment to allow only the registered frontend origin

## 7. Database Design

The schema follows a normalised relational hierarchy aligned with the MCA academic structure:

```
users
  └── quiz_attempts  → subject → unit → topic
  └── notes          → subject → topic
  └── user_progress  → subject
  └── topic_progress → subject → topic
  └── chat_history   → subject
  └── quizzes        → subject → topic
semesters → elective_groups → subjects → units → topics
```

Key design decisions:
- All passwords stored as bcrypt hashes — never plaintext
- CASCADE DELETE on all child tables for referential integrity
- UNIQUE constraints prevent duplicate progress records per user/subject
- JSONB column on quiz_attempts stores per-question answers for review mode
- topic_progress enables granular weak-area detection per topic

Tables: users, semesters, elective_groups, subjects, units, topics, notes,
        quizzes, quiz_attempts, user_progress, topic_progress, chat_history

## 8. Functional Modules

### 8.1 User Authentication
- Signup with bcrypt password hashing + email validation
- Login returns a signed JWT (expires in 6 hours)
- All protected routes use @jwt_required() decorator
- Frontend Axios interceptor auto-attaches the Bearer token
- 401 responses trigger automatic logout and redirect to /login

### 8.2 AI Study Note Generation
- User selects subject and topic from the MCA syllabus
- Flask calls Groq API with an exam-focused prompt
- Response is saved to the notes table and displayed in Markdown
- Notes are searchable, copyable, and exportable as PDF (print)

### 8.3 Adaptive Quiz Engine
- AI generates structured JSON MCQs for the selected topic and difficulty
- Quiz content stored in PostgreSQL; retrieval via left join
- On submission: score saved to quiz_attempts, progress recalculated
- Retry mode replays saved quizzes from history
- Helpers module generates performance feedback (strong/average/weak)

### 8.4 AI Chat Tutor
- Multi-turn conversational interface with subject context
- Last 6 messages sent as history for conversational continuity
- Every Q&A exchange saved to chat_history table
- Rate limited to 20 requests/minute

### 8.5 Performance Analytics
- Score trend chart (SVG, last 10 attempts)
- 14-week activity heatmap
- Subject-wise performance ranking
- Strong/Average/Weak attempt breakdown
- All metrics computed from live quiz_attempts data

### 8.6 FYP Guide
- User inputs domain, interest, and team size
- AI generates a structured Final Year Project roadmap
- Output includes title suggestions, tech stack, timeline, and risks

### 8.7 Resume Builder
- Multi-step form collects education, skills, projects, experience
- AI generates an ATS-optimised LaTeX resume
- User can download .tex source or open directly in Overleaf
- Existing resume improvement mode also supported

## 9. Security Implementation

| Concern             | Implementation                              |
|---------------------|---------------------------------------------|
| Password storage    | bcrypt with random salt per user            |
| Authentication      | JWT (HS256), 6-hour expiry                  |
| Authorisation       | @jwt_required() on all data endpoints       |
| Ownership checks    | DELETE queries include AND user_id = %s     |
| API abuse           | Flask-Limiter — 10/min on AI routes         |
| Input validation    | Email regex validation on signup            |
| Secrets management  | All keys via environment variables (.env)   |
| CORS                | Restricted to registered frontend origin    |

---

## 10. Deployment

- Frontend built with `npm run build`, deployed via Vercel (automatic on git push)
- Backend served by Gunicorn on Render (Web Service, free tier)
- Database hosted on Neon (serverless PostgreSQL, auto-sleep on inactivity)
- Environment variables configured per-service on Render and Vercel dashboards
- CORS configured via FRONTEND_URL environment variable

---

## 11. Limitations

- AI accuracy depends on LLaMA 3.1 8B model quality; critical content should be verified
- LaTeX compilation requires Overleaf (pdflatex not available on Render free tier)
- Neon database auto-sleeps after inactivity; first request on free tier may be slow
- No offline support or PWA functionality
- No real-time collaborative features
