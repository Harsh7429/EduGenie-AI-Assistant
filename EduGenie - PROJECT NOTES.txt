## SETUP & DEPLOYMENT NOTES

### Local Development Setup

**Backend:**
  cd backend
  python -m venv venv
  venv\Scripts\activate        (Windows)
  source venv/bin/activate     (Mac/Linux)
  pip install -r requirements.txt
  copy .env.example .env       (fill in real values)
  python app.py

**Frontend:**
  cd frontend
  npm install
  npm run dev

**Database:**
  Create a PostgreSQL database named edugenie_db
  Run: psql -U postgres -d edugenie_db -f backend/schema.sql

---

### Production Deployment

**Frontend → Vercel**
- Connect GitHub repo to Vercel
- Set environment variable: VITE_API_URL = https://your-render-backend.onrender.com
- Vercel auto-deploys on every push to main

**Backend → Render**
- Create a Web Service on render.com
- Start command: gunicorn app:app
- Set all environment variables from .env in Render dashboard
- GROQ_API_KEY, JWT_SECRET_KEY, DB_HOST, DB_NAME, DB_USER, DB_PASSWORD, FRONTEND_URL

**Database → Neon (Serverless PostgreSQL)**
- Create a project on neon.tech
- Copy connection string values to Render environment variables
- Note: Neon auto-sleeps on free tier — first cold-start request may take 2-3 seconds

## AI / GROQ NOTES

- AI model: LLaMA 3.1 8B Instant via Groq API
- Groq offers free-tier inference with very low latency (LPU hardware)
- API key from: https://console.groq.com
- AI is called server-side only — key never exposed to browser
- Rate limits applied via Flask-Limiter: 10 req/min for notes/quiz, 20 req/min for chat
- If Groq rate limit is hit, the API returns 429 — frontend shows a friendly error

## KNOWN ISSUES & WORKAROUNDS

**Cold starts on Render free tier:**
  Render free tier spins down after 15 min of inactivity.
  First request after sleep takes 30-50 seconds to respond.
  Workaround: Use a UptimeRobot ping every 10 minutes, or upgrade to paid tier.

**LaTeX compilation not available in production:**
  pdflatex is not installed on Render free tier.
  Resume Compile endpoint returns a 422 with the LaTeX source and an Overleaf link.
  Users paste the LaTeX into Overleaf to download the PDF.
  This is by design and is communicated in the UI.

**Neon cold start:**
  Neon serverless PostgreSQL also sleeps on free tier.
  First DB query after sleep adds ~1 second latency.
  Subsequent queries are fast.

## AUTH FLOW

1. User submits signup form → email/password validation (frontend + backend)
2. Password hashed with bcrypt → stored in users table
3. Login returns JWT signed with JWT_SECRET_KEY (HS256, 6-hour expiry)
4. Token stored in localStorage by frontend
5. Axios interceptor adds Authorization: Bearer <token> to every request
6. @jwt_required() decorator on all Flask routes verifies the token
7. get_jwt_identity() returns user_id (string) → cast to int for DB queries
8. On 401 response, frontend clears token and redirects to /login

## PROGRESS TRACKING LOGIC

After every quiz submission (POST /quizzes/<id>/submit):

1. Score saved to quiz_attempts
2. avg_score = AVG(score) from all quiz_attempts for this user + subject
3. attempted_topics = COUNT DISTINCT topic_id from quiz_attempts for this user + subject
4. total_topics = COUNT topics where unit.subject_id = this subject
5. progress_pct = (attempted_topics / total_topics) * 100
6. user_progress upserted with new avg_score and progress_pct
7. Response includes: average_score, progress_percentage, feedback, performance_level, next_difficulty

## FEATURE NOTES

**Streak System:**
  Streak increments once per day when a quiz is generated (GenerateQuiz.jsx).
  Stored in localStorage (eg_streak, eg_streak_day).
  Not server-backed — resets if localStorage is cleared.
  Acceptable for demo/presentation purposes.

**PDF Export (Notes):**
  Uses window.print() with a print-specific CSS stylesheet.
  No external PDF library needed.

**FYP Guide:**
  Last 5 guides stored in localStorage for quick recall.
  Exportable as .md file.

**Quiz Review Mode:**
  After submitting, each question shows the correct answer and explanation.
  Retry mode reloads a saved quiz from /quizzes endpoint.

## VIVA TALKING POINTS

- Why Groq over OpenAI? → Free tier, extremely fast LPU inference, LLaMA 3 is open-source
- Why PostgreSQL? → ACID compliance, relational integrity, standard in production systems; Neon provides serverless hosting
- How is AI accuracy ensured? → LLM handles well-established MCA syllabus topics; users advised to verify critical content
- How does progress tracking work? → See PROGRESS TRACKING LOGIC above
- What happens if AI is unavailable? → Flask catches exceptions and returns a 500 with a user-friendly message; no data loss
- How is the JWT stored securely? → localStorage (acceptable for academic demo); production would use httpOnly cookies
- Rate limiting strategy → Flask-Limiter with in-memory store; 10/min on AI routes prevents API quota exhaustion
